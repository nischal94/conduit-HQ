# Conduit

**The open-source integration layer for AI agents: one catalog for every
tool, shared across every agent you use — with the guardrails built in.**

Most agent setups force a choice between locked-down-and-useless and
wide-open-and-risky. Conduit dissolves that dichotomy: configure each
integration once (MCP servers today; OpenAPI/GraphQL per the spec), with
authentication and per-tool policies, then use that same catalog from any
MCP-compatible agent. Every call flows through one gateway, so the same
guardrails apply everywhere. The whole idea: **make the safe path the easy
path.**

## What it does today

- **One catalog, any agent.** `conduit add-mcp` onboards an upstream MCP
  server (real-world streamable-HTTP servers — GitHub, Context7 — verified
  live); `conduit serve` exposes the whole catalog to any MCP client as a
  two-tool search-and-execute surface with progressive disclosure.
- **A real credential boundary.** Upstream secrets are sealed
  (libsodium-style secretbox) into a local SQLite store under a master key
  (`~/.conduit/master-key`, 0600, `conduit key generate` / `conduit key
  rotate`). Secrets are injected at the gateway edge only — they never
  reach the agent, the model, or agent-authored code. Spec §9.2; pinned by
  invariant tests.
- **Policy engine with a human in the loop.** Per-tool
  allow / require-approval / block; paused calls wait in an approval queue
  (`conduit approvals list|approve|deny`) and resume or fail loudly.
- **Sandboxed execution.** Agent-authored orchestration runs in a QuickJS
  sandbox with hard resource limits (spec §16) and no ambient authority.
- **Egress control.** Fail-closed SSRF defaults: the upstream caller
  resolves once, checks the resolved IP, and pins the connection
  (spec §9.3).
- **Trace, day one.** Every execution and tool call is recorded with
  write-time secret redaction (spec §11) — auditable after the fact, not
  "coming soon".

## Status

Pre-1.0, moving fast, **not yet published to npm** (`@conduithq/*` is the
reserved scope). Run from source:

```bash
pnpm install --frozen-lockfile --ignore-scripts
pnpm -r build
node packages/cli/dist/bin.js --help
```

Requires Node (see `.nvmrc`) and pnpm. Start with
[`packages/cli/README.md`](packages/cli/README.md) for the quick start,
and [`conduitspec.md`](conduitspec.md) — the full technical specification
and the repo's source of truth.

## Repo map

| Path | What it is |
| --- | --- |
| `packages/sdk` | Core: store, sealing, policy, sandbox, pipeline, MCP upstream client |
| `packages/mcp` | The stdio MCP server (`conduit serve`) |
| `packages/cli` | The `conduit` command |
| `conduitspec.html` / `.md` | The technical spec (HTML is source; `.md` generated by `html2md.py`) |
| `INVARIANTS.md` | Ledger mapping load-bearing spec claims to their pinned tests |
| `HANDOFF.md` / `LEARNINGS.md` | The live build-in-the-open session log and lessons ledger |

## Built in the open

This repo is developed AI-agent-first under an unusually strict pipeline —
spec-recorded decisions, invariant-pinned security claims, multi-model
adversarial review, and a human who owns every merge. `HANDOFF.md` and
`LEARNINGS.md` are the unedited working record of that process, public on
purpose.
